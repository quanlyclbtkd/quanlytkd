## QuickPay business semantics frozen

- Current custom amount behavior is **not changed in C1F1**. For a one-month command, even an amount below the configured monthly fee still targets that selected month; for multi-month commands the existing `floor(amount / feePerMonth)` logic determines how many leading months are considered paid.
- C1F1 therefore does **not** infer idempotency from `paidUntil` or `paidMonths` and does not change partial/override semantics.
- Payment success remains the canonical result of the existing atomic command. Receipt state never becomes payment truth.
