## Additional audit findings

- Primary write authority remains `js/modules/finance.js → TuitionCommandBoundary → FinanceService.commitAtomicWritePlan()`.
- Existing `completedReplay` remains a short-lived process-memory optimization; it must not become financial truth.
- F1A Layer-2 settlement already uses `window.TuitionDebtCanonical.areTuitionMonthsSettled(...)`, so F1B will extend that owner rather than create a second resolver.
- Current QuickPay write shape includes `description`, `txMonth`, and `packageMonths`; many historical tuition writers also use these fields. Stable profile identity fields are not guaranteed on every legacy transaction.
- `reconcileStudentTuitionAfterDeletedTransaction()` now commits local paid state only after its Firestore profile update succeeds, preserving the F1A fail-closed guarantee.
- Existing fallback branch in `deleteTuitionTransaction()` can call `FinanceService.getStudentTuitionTxs()`; F1B will not add any additional Firestore read and will not widen this legacy path.
- Same-runtime concurrency can be closed with a client-local profile lane. Cross-device concurrency remains OUT OF SCOPE / NOT VERIFIED by design.
