## Inventory rollback contract finding before patch
`InventoryService.deleteItem(invId, { previous, relatedTxId })` uses one Firestore `writeBatch` to delete the inventory item, reverse `inventory_stats`, and optionally delete the related Finance transaction. If `previous` is omitted it performs a fallback `getDoc`; F1D1 therefore may only use this owner without new reads when the inventory record is already available in canonical local runtime state. Multiple refs, missing local inventory evidence, mixed Tuition+Inventory, or identity conflicts must fail closed before any destructive write.
