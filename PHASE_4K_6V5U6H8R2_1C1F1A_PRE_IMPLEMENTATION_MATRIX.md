## Current authority conclusions
- Primary payment writer remains `finance.js -> TuitionCommandBoundary.collectTuition() -> FinanceService.commitAtomicWritePlan()`.
- Existing delete owner is `TuitionCommandBoundary.deleteTuitionTransaction()` for tuition-only transactions.
- Existing delete path already performs Firestore reconciliation reads; F1A adds **zero** new reads.
- Existing canonical profile state is already available in `studentProfileStore / __store.profiles / allProfiles`.
- `TuitionDebtCanonical` is the correct existing owner to expose specific-month settlement semantics; a second resolver in Finance/QuickPay would violate the authority freeze.
