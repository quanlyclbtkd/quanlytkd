## Proven pre-patch residual defects

- **D1A-01 / P1:** actual `processMultiItem` handler can throw `TypeError: Assignment to constant variable` because `profile` is declared `const` and reassigned to `latestProfile` inside the tuition lane.
- **D1A-02 / P1:** canonical inventory relationship exists in `TransactionDeleteIntegrity`, but the active module `inventoryRenderer` independently maps only `tx.relatedInvId`; nested-only linkage is therefore missed.
- **D1A-03 / P1:** active renderer can emit `deleteTx('undefined', inventoryId)` for an Inventory row with no resolved Finance tx.
- **D1A-04 / P1:** `TransactionDeleteIntegrity.analyzeTransactionDeleteImpact({})` currently yields `safeToHardDelete:true`; an empty transaction object is not valid destructive-delete evidence and must fail closed.
- **D1A-05:** Finance delete coordinator does not yet reject `undefined/null/"undefined"/"null"/""` transaction IDs before service routing.
- **D1A-06:** inventory row with no Finance tx needs an explicit intent contract: safe direct `InventoryService` only when local item is present and no protected linkage exists; otherwise fail closed.
- **D1A-07:** authenticated RV01–RV20 still missing; source/static evidence cannot close receipt visibility.
- **D1A-08:** Rules R1–R11 environment status must be re-probed; prior environment lacked Firebase CLI.
